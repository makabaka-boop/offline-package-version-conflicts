# 离线软件包依赖求解器

一个只使用 Python 标准库的命令行/容器求解器。它读取一份离线目录 JSON，输出满足根需求和依赖闭区间约束的完整可安装集合；若不存在这样的集合，只输出 `UNRESOLVABLE`。

## 目录限制

- 最多 10 个唯一包名；包名必须为非空、可见 ASCII 字符（不含空格）。
- 每个包有 1～4 个正整数版本。
- 每个版本可声明 0 个或多个依赖，依赖要求为闭区间 `[lower, upper]`。
- 根需求也使用闭区间。
- 依赖环允许；环上每个被选版本必须被所有入边区间接受。
- 最终集合必须**恰为**根需求沿所选版本依赖可达的闭包：不能缺少被依赖包，也不能保留闭包外的已装包。
- 可选的 `conflicts` 声明已知不兼容的版本组合：每对的两个具体版本不得同时安装。冲突是双向互斥约束，不产生依赖，也不允许保留闭包外的包。

## 优化目标（按优先级）

在所有可行解中依次选择：

1. **变更包数最少**：相对 `installed`，新增、删除、改版都算 1 个包。
2. **最终包数最少**。
3. **版本向量字典序最大**：按目录中全部包名排序，未安装位置记作版本 `0`。

例如目录名顺序为 `("a", "b")` 时，只安装 `b=2` 的向量是 `(0, 2)`。

`installed` 中允许出现目录里已经不存在的版本号（视为过期安装，升级或删除算一次变更）；但 `installed` 中的包名、根需求包名和依赖包名都必须在目录内，否则按格式错误直接拒绝。根需求为空对象是合法输入，表示目标闭包为空，当前已装包都应删除。

## 输入格式

```json
{
  "packages": {
    "app": {
      "1": {"dependencies": {"lib": [1, 2]}},
      "2": {"dependencies": {}}
    },
    "lib": {
      "1": {"dependencies": {}},
      "2": {"dependencies": {}}
    }
  },
  "root": {
    "app": [1, 2]
  },
  "installed": {
    "app": 1
  },
  "conflicts": [
    [{"package": "app", "version": 1}, {"package": "lib", "version": 2}]
  ]
}
```

- `packages`、`root`、`installed` 三个顶层字段均为必填；`conflicts` 可省略；不允许未知字段。
- `dependencies` 可省略或为空对象。
- 版本键必须是无符号正整数的十进制字符串（如 `"1"`，不接受 `"01"`、`"1.0"`）。
- 区间必须是恰好两个整数组成的数组，且满足 `1 <= lower <= upper`。
- 布尔值不会被当作整数接受；JSON 重复对象键会被拒绝。
- `conflicts` 可省略或为空数组；每项是恰好两个 `{"package", "version"}` 端点组成的数组：
  - 两个端点必须属于**不同**的包，且版本必须是该包在目录中存在的版本；
  - 整份列表不允许重复，包括端点逆序后的重复；
  - 省略 `conflicts` 的旧输入与输出保持逐字兼容。

## 输出与退出码

- 有解：标准输出打印一个 JSON 对象，键按包名字典序排列，如 `{"app": 2, "lib": 2}`；退出码 `0`。
- 无解：标准输出打印一行 `UNRESOLVABLE`；退出码 `0`。不会输出部分计划。根需求与冲突共同无解时同样只输出 `UNRESOLVABLE`。
- JSON/契约格式错误、目录外依赖、非法冲突声明（未知包、未知版本、同包冲突、逆序重复等）：错误信息写入标准错误；退出码 `2`；标准输出不产生计划。

## 本地运行

```bash
# 从标准输入读取
PYTHONPATH=src python3 -m resolver < examples/request.json

# 或传入文件路径
PYTHONPATH=src python3 -m resolver examples/request.json
```

## Docker Compose

```bash
# 构建
docker compose build resolver

# 通过标准输入运行
docker compose run --rm resolver < examples/request.json

# 或挂载文件并传路径
docker compose run --rm -v "$PWD:/work" resolver /work/examples/request.json
```

## 测试

测试中的“对拍”会对小目录枚举每个包的“不安装/选择某个版本”的全部组合，执行根可达闭包、全部区间检查和冲突互斥检查，再按相同目标选出答案，与回溯求解器结果逐一比较。覆盖：

- 3 包 × 最多 3 版本、5 包 × 最多 4 版本的 90 个随机小目录（含随机生成的冲突对）；
- 自环、互相依赖环、冲突区间、空根；
- 删除不再可达的包、过期已装版本、包数 tie-break、完整目录向量字典序；
- 冲突排除特定版本组合、冲突导致的回滚、冲突与依赖环/过期已装版本的组合、冲突不产生依赖也不保留闭包外的包；
- CLI 成功、`UNRESOLVABLE` 和格式错误退出码。

有 pytest 时：

```bash
python3 -m pytest
# 或使用 Compose（容器内安装 pytest）
docker compose run --rm test
```

在没有 pytest、也不能联网安装的环境中，仓库提供了仅用于本测试集的标准库兼容运行器：

```bash
python3 run_tests.py
```

## 算法说明

求解器使用约束传播 + 深度优先回溯：

- 对每个已被根或依赖要求的包维护交集区间（所有下确界取 max、上确界取 min）。
- 每选一个版本，立即加入其依赖边；若区间变为空，或与已选依赖版本冲突，则回滚。
- 每选一个版本，同时检查它是否与已选版本构成 `conflicts` 互斥对；若某个必选包因此不再存在无冲突的可行版本，同样回滚。冲突检查在选择与传播过程中完成，而不是先求旧最优再删除冲突包。
- 待选包采用“可行版本最少优先”（MRV）以尽早发现冲突。
- 分支内版本从大到小尝试，以便先找到字典序较大的候选。
- 分支定界使用安全下界：
  - 当前必选包中无法保持已装版本的数量；
  - 当前闭包大小；
  - 乐观版本向量上界。
  这些剪枝只排除不可能优于当前最优解的分支，不改变穷举语义。

目录上限只有 10 包 × 4 版本（约一百万组合量级），最坏无依赖情形下纯穷举约 6 秒；加入上述剪枝后典型/边界基准为毫秒级。
